04

PetCare API — duas stacks, um domínio

Autor único · Decisão de arquitetura

A mesma API REST para uma clínica veterinária, construída duas vezes de propósito. No Trabalho 1, em PHP puro: CRUD completo, banco próprio e autenticação por token. No Trabalho 2, reconstruí o mesmo domínio em Python com FastAPI — decidindo eu mesmo a arquitetura: pastas separadas por responsabilidade, acesso ao banco com SQL puro via psycopg2 (sem ORM) e o mesmo esquema de autenticação. O frontend dessa versão escrevo sozinho, usando apoio só como tutoria.

Liderança

Por que eu sempre acabo liderando o time

Não é por acaso que PCI-LEADS, Casa dos Frios e Data Guardian têm o mesmo padrão: eu na liderança técnica, decidindo arquitetura e tecnologia. É uma escolha deliberada sobre como quero trabalhar.

01 / PROCESSO

Fluxo de equipe de verdade

Branches, issues e pull requests revisados — mesmo em projetos de empresa júnior e faculdade. No PCI-LEADS, montei esse fluxo de propósito para dar ao time uma experiência real de trabalho em software, não um projeto de sala de aula.

02 / DECISÃO

Arquitetura é minha responsabilidade

Em quase todo projeto que lidero, sou eu quem decide a stack e o desenho técnico — do SQL puro sem ORM no PetCare FastAPI à divisão de responsabilidades do Data Guardian.

03 / MENTORIA

Formar quem está aprendendo

Indico documentação, reviso pull requests e acompanho a evolução de colegas com menos experiência — como no acompanhamento que dou ao Pedro Esmeraldo dentro do PCI-LEADS.
